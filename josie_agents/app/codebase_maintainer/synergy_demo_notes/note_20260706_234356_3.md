## P0 - 立即实现（高风险/低成本）

### 1. API 客户端重试机制
- **位置**: api_client.py L41
- **理由**: 网络抖动是常见问题，无重试导致服务脆弱
- **方案**: 使用 `tenacity` 库或手写指数退避
- **影响**: 所有 API 调用健壮性提升

### 2. Product 折扣边界验证
- **位置**: models.py L50
- **理由**: 当前可传入非法值（如 -50% 或 150%），可能产生负价或异常订单
- **方案**: 验证 0 <= percentage <= 100，非法值 raise ValueError
- **影响**: 防止财务计算错误

### 3. Order 金额计算（含税费/折扣）
- **位置**: models.py L66
- **理由**: 财务计算错误是严重业务问题
- **方案**: 引入税率常量 + 支持每个 Product 的折扣
- **影响**: 订单金额准确性

## P1 - 近期实现（核心功能）

### 4. Transaction 退款功能
- **位置**: models.py L84
- **理由**: 电商核心业务，缺失会阻塞完整支付流程
- **方案**: 添加 `refund()` 方法 + status 状态机（pending → refunded）
- **依赖**: 需先确定支付网关集成方案

### 5. User 用户验证
- **位置**: models.py L23
- **理由**: 用户系统必备功能
- **方案**: validate_email() + password_strength() 等方法
- **可复用**: utils.validate_email 已存在

### 6. 数据验证逻辑（data_processor）
- **位置**: data_processor.py L20
- **理由**: 入口函数，影响所有下游处理
- **方案**: 用 pydantic 或手写 schema 校验必填字段、类型
